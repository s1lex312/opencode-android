# Smoke-тест на устройстве

Чек-лист для ручной проверки сборки на реальном Android-устройстве. CI проверяет только
компиляцию и unit-тесты; всё, что ниже — сеть, UI и Keystore, — проверяется руками.

Обозначения: ⬜ не проверено, ✅ ок, ❌ проблема (заводите issue/пункт в TODO.md).

## 0. Подготовка

- [ ] `./gradlew assembleDebug` (или APK из CI-артефакта) установлен: `adb install -r app-debug.apk`.
- [ ] На сервере: `opencode serve --hostname 0.0.0.0 --port 4096`, тот же Wi-Fi.
- [ ] `adb logcat | grep -i opencode` открыт в отдельном окне — приложение не должно печатать
      пароль/токен.

## 1. Запуск и навигация

- [ ] Приложение стартует без краша; открывается экран сессий.
- [ ] Пустое состояние: «Not connected» + кнопка «Open settings».
- [ ] Settings открывается, поля скроллятся, крупный системный шрифт не ломает вёрстку.
- [ ] Тёмная/светлая тема (системная) выглядит корректно.
- [ ] Поворот экрана сохраняет текст, введённый в поле адреса/промпта.

## 2. Настройки и подключение

- [ ] Ввести `http://<LAN-IP>:4096` → **Test** → «Reachable: opencode vX (API v2)»
      (для старого сервера — legacy API).
- [ ] Неверный пароль → понятная ошибка (401), приложение не крашится.
- [ ] Публичный `http://example.com` → отказ ещё до запроса (NetworkPolicy), сообщение понятное.
- [ ] `https://` адрес с самоподписанным сертификатом → отказ TLS с текстом ошибки.
- [ ] **Save & connect** → бейдж «connected».
- [ ] Перезапуск приложения → адрес и режим аутентификации сохранились.
- [ ] Пароль сохранён: после перезапуска соединение проходит без повторного ввода.
- [ ] `adb shell run-as ai.opencode.android.debug cat shared_prefs/*.xml` — пароля в открытом
      виде нет.

## 3. Сессии

- [ ] Список сессий загружается, сортировка по времени обновления.
- [ ] Создание сессии (FAB) → открывается чат.
- [ ] Удаление сессии (меню карточки) → подтверждение → исчезает из списка.
- [ ] Pull-to-refresh / кнопка Refresh обновляет список.
- [ ] Остановить сервер → бейдж «offline»/«reconnecting», показываются кэшированные сессии и
      баннер «Showing cached sessions».
- [ ] Запустить сервер → автопереподключение без перезапуска приложения.

## 4. Чат и стриминг

- [ ] Отправить «прочитай README и перескажи в двух предложениях» → текст появляется по мере
      генерации (дельты), без «дёрганья» по пустому экрану.
- [ ] Длинный ответ: прокрутка вверх не ломается; композер остаётся на месте.
- [ ] Карточка tool-call: название, статус (streaming/running/completed/error), раскрытие
      показывает ввод/вывод; «Completed» зелёный, «Error» красный.
- [ ] Кнопка Stop во время генерации → сервер перестаёт работать, в ленте появляется
      соответствующее состояние.
- [ ] Ошибка модели на сервере (например, неверный ключ) → текст ошибки в ленте, а не пустота.
- [ ] Отключить сеть во время стриминга → «reconnecting», затем восстановление и корректная
      история (сервер — источник истины).
- [ ] Клавиатура не перекрывает поле ввода (edge-to-edge + imePadding).
- [ ] Enter на физической/экранной клавиатуре не отправляет пустое сообщение.

## 5. Разрешения (permissions)

- [ ] Задача, требующая подтверждения (например, «выполни `ls -la`») → появляется карточка.
- [ ] **Allow once** → инструмент выполняется.
- [ ] **Always** → повторный вызов не спрашивает (политика сохраняется до перезапуска).
- [ ] **Reject** → агент получает отказ, лента продолжается.
- [ ] Политика `AUTO_ALLOW` в настройках → карточки не появляются, всё разрешается.
- [ ] Политика `DENY` → все запросы автоматически отклоняются.

## 6. Diff

- [ ] Кнопка «Session diff» открывает список файлов с числом добавлений/удалений.
- [ ] Добавленные строки зелёные, удалённые красные, контекст нейтральный; номера строк есть.
- [ ] Большой патч (сотни строк) прокручивается без лагов; хунки разделены заголовками.
- [ ] Бинарный файл помечен «binary».
- [ ] Пустой diff → понятное пустое состояние.

## 7. Встроенный сервер (опционально, arm64)

- [ ] `server/scripts/install-on-device.sh` положил rootfs и proot.
- [ ] Settings → Local server → **Start** → `Starting…` → `Running (healthy)`.
- [ ] В логах нет ошибок proot; в шторке висит уведомление с «Stop».
- [ ] Подключение к `http://127.0.0.1:4096` из приложения работает.
- [ ] **Stop** гасит процесс, уведомление исчезает.
- [ ] Неверный путь к rootfs → `FAILED` с текстом про `server/README.md`.

## 8. Производительность и стабильность

- [ ] 100+ сообщений в сессии: прокрутка плавная, память не растёт бесконечно.
- [ ] Свернуть/развернуть приложение во время стриминга → SSE переподключается, история верна.
- [ ] 15 минут в фоне → возврат в приложение не вешает UI.
- [ ] `adb shell dumpsys meminfo ai.opencode.android.debug` после 10 минут работы: без утечек
      соединений (OkHttp dispatcher не растёт бесконечно).

## 9. Что делать с найденными проблемами

1. Воспроизвести и записать шаги, версию сервера (`/api/info` или `opencode --version`),
   `adb logcat` вокруг ошибки (без секретов).
2. Добавить пункт в `TODO.md` (или issue) с приоритетом.
3. Если ошибка в контракте API — обновить `ASSUMPTIONS.md` и маппер в `data/events`.
