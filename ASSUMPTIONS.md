# Допущения

Каждое допущение зафиксировано здесь, чтобы решения можно было пересмотреть без археологии по
коду. Если реальность отличается — правьте соответствующий пункт и код.

## 1. «opencode 8.0+» — трактовка версии

Публичных релизов opencode с номером 8.x нет: на момент работы актуальны релизы **2.2.x**
(клиент `@opencode/cli` 2.2.5, API `HttpApi`), а npm-пакет `@opencode-ai/sdk` живёт на
1.19.x (legacy REST). Поэтому требование «opencode 8.0+» трактуется как **«современный сервер
opencode»**, и клиент поддерживает обе реальные поверхности:

* v2 `HttpApi` (`/api/session`, `/api/event`, `/api/model`, `/api/info`) — актуальные серверы;
* legacy REST (`/session`, `/event`, `/config/providers`) — серверы 0.x/1.x.

Версия определяется автоматически при подключении; в UI показывается `API v2` / `legacy API`.
Контракты сверены с `packages/protocol/openapi.json` и типами `@opencode-ai/sdk`.

## 2. Транспорт и форматы

* Сервер отдаёт JSON; SSE-кадры — `data: {json}\n\n`, тип события лежит в поле `type` самого
  JSON (SSE-поле `event:` не используется, но поддерживается парсером).
* Heartbeat-комментарии (`: heartbeat`) игнорируются.
* У v2 события имеют вид `{id, created, type, data:{...}}`, у legacy — `{type, properties:{...}}`;
  глобальный вариант `{directory, payload:{...}}` разворачивается автоматически.
* Успешные ответы v2 часто обёрнуты в `{data: ...}`; клиент разворачивает обёртку там, где она есть.

## 3. Аутентификация

* `opencode serve` включает HTTP Basic, если задан пароль. Логин фиксирован сервером —
  `opencode`; пароль берётся из `OPENCODE_PASSWORD` (или legacy `OPENCODE_SERVER_PASSWORD`).
* Клиент поддерживает три режима: `None`, `Basic` (логин + пароль), `Bearer` (для reverse-proxy
  с токеном).
* Параметр `auth_token` (base64 `user:pass`) сервер тоже принимает, но приложение его не
  использует: заголовок `Authorization` надёжнее и не попадает в логи URL.
* Пароль/токен не передаются в query-строке.

## 4. Сеть и адреса

* Порт по умолчанию — **4096** (как у `opencode serve`), если пользователь не указал иной.
* Отсутствующая схема достраивается: `http://` для loopback и приватных диапазонов,
  `https://` для всего остального.
* Открытый HTTP к публичным хостам запрещён всегда; к локальной сети — разрешён по умолчанию,
  но переключателем в настройках можно включить строгий режим (только HTTPS/localhost).
  Это компромисс: типовой сценарий — сервер на ноутбуке в той же Wi-Fi.
* Android network security config не умеет выражать «приватные диапазоны», поэтому
  `usesCleartextTraffic=true`, а реальный контроль — в `NetworkPolicy` + интерсепторе.

## 5. Аутентификация и хранение секретов

* Секреты — только `EncryptedSharedPreferences` (`androidx.security:security-crypto`) с
  мастер-ключом в Android Keystore. Если Keystore сломан/недоступен (например, после restore),
  приложение работает в режиме «только память» и явно об этом сообщает.
* Данные приложения исключены из бэкапа (`allowBackup=false`, `dataExtractionRules`).
* Секреты не логируются; отладочный лог пишет только method/path/status/время.

## 6. Хранилище состояния: DataStore вместо Room

Room не используется. Причины:

* мобильный клиент — тонкая проекция серверного состояния; кэшировать историю сообщений
  означает поддерживать второй источник истины и миграции;
* для единственного кэша (список сессий) достаточно JSON-файла в `cacheDir`;
* меньше зависимостей и нет KSP/annotation processing в сборке.

Если появится полноценный офлайн-режим (пункт в TODO), Room станет оправдан — тогда и добавим.

## 7. Стриминг и проекции сообщений

* В v2 текст приходит дельтами (`session.text.delta`) и финальным `session.text.ended`.
  Идентификатор части для дельт синтезируется как `text-{ordinal}`.
* Проекция сообщений (`/message`) — источник истины; после `session.idle`,
  `session.execution.*`, `session.step.ended` ViewModel перезапрашивает её. Локальный редуктор
  существует только для плавности, поэтому возможен короткий визуальный «прыжок» при
  перезапросе во время длинного ответа.
* У legacy-серверов часть `text` приходит кумулятивно + `delta`; редуктор умеет и то, и другое.
* В v2 части сообщений не имеют собственных id — используется позиционный id
  `{messageId}:part-{index}`. На отображение это не влияет, потому что история перезагружается
  целиком.

## 8. Модели и агенты

* v2 не принимает модель в теле промпта: перед отправкой клиент вызывает
  `POST /api/session/{id}/model` (и `/agent`, если выбран агент). Ошибки этих вызовов
  игнорируются, чтобы не блокировать отправку сообщения.
* Каталог моделей: v2 — `GET /api/model`, legacy — `GET /config/providers`. Если сервер ничего
  не вернул, приложение работает на дефолтной модели сервера.
* Модель/агент хранятся глобально в настройках приложения, а не в каждой сессии.

## 9. Разрешения (permissions)

* Политика `ASK` показывает карточку и ждёт решения; `AUTO_ALLOW` отвечает `once`;
  `DENY` отвечает `reject`.
* Ответы: v2 — `POST /api/session/{id}/permission/{requestID}/reply` с `{decision}`;
  legacy — `POST /session/{id}/permissions/{permissionID}` с `{response}`.
* Значения `once` / `always` / `reject` взяты из типов сервера (`Permission.Reply`).

## 10. Diff

* Источник diff — `FileDiff.patch` (unified diff). Ожидается текст, который отдаёт git.
* Бинарные файлы показываются как «binary», без содержимого.
* Полнофайловые патчи (без `@@`) отображаются как raw-текст, если парсер не нашёл хунков.
* Парсер не бросает исключений: битый патч не должен ронять экран.

## 11. Local mode: провижининг и запуск сервера

* **Режим по умолчанию — Local.** Приложение само ставит и запускает сервер; Remote остаётся
  полноценной опцией в настройках. Миграция: если у пользователя уже был сохранён адрес
  сервера (ключ `server_url`), режим считается Remote, иначе Local.
* **Bundle не входит в APK.** Причина — сотни мегабайт и лицензии сторонних бинарников. Bundle
  собирается скриптом (`server/scripts/build-rootfs.sh`) и либо кладётся в `assets`, либо
  публикуется; приложение скачивает его по HTTPS с обязательной проверкой SHA-256.
* **Структура bundle** (зафиксирована в коде и скрипте, `TarGzExtractor` + `EnvProvisioner`):
  `proot` в корне, `rootfs/` с `/bin/sh` и `rootfs/usr/local/bin/opencode`, опционально
  `proot-libs/*.so`. proot может быть динамическим: `proot-libs/` устанавливается в
  `opencode-env/proot/lib/`, и приложение выставляет `LD_LIBRARY_PATH` на этот каталог.
  Готовый bundle собирает CI из Termux-пакета `proot` (arm64/bionic), поэтому бинарь ожидает
  bionic, а не glibc.
* **opencode внутри bundle — standalone-бинарь** `opencode-linux-arm64` из релизов проекта
  (Bun-compiled), а не npm-пакет: не нужен Node/Bun внутри rootfs, экономия ~200 МБ. Если у
  пользователя свой rootfs с `opencode` в `PATH`, bundle всё равно валиден.
* **proot должен быть для Android/arm64.** CI использует сборку Termux (bionic) + её `.so`; вариант
  со статическим proot возможен, но требует статического `libtalloc` под aarch64, которого нет в
  Ubuntu-репозиториях (кросс-сборка talloc через waf не даёт `.a`). Артефакт проверяется по
  `docs/SMOKE-TEST.md`.
* **Health-check: `GET /`** (затем `/api/info`, `/config`). 200–499 = сервер жив; 401 тоже
  считается здоровым (просто нет креденшелов). Health опрашивается каждую секунду до 180 с,
  затем каждые 5 с; 3 подряд неудачи → перезапуск.
* **Пароль сервера** генерируется приложением (32 символа, `SecureRandom`) при первом запуске
  Local mode, хранится в `EncryptedSharedPreferences`, передаётся дочернему процессу через
  `OPENCODE_PASSWORD` (и дублируется в `OPENCODE_SERVER_PASSWORD` для совместимости версий).
  Предполагается, что `opencode serve` берёт пароль из этих переменных; если конкретная версия
  использует другой способ, пароль всё равно остаётся в окружении процесса и не логируется.
* **Пути**: окружение — `noBackupFilesDir/opencode-env` (rootfs, proot, `installed.json`, `logs/`).
  Пути в настройках (`rootfsPath`, `prootPath`) оставлены как override для отладки, но по
  умолчанию пусты.
* **Порт** — 4096, конфигурируемый; сервер слушает только `127.0.0.1`, поэтому трафик не выходит
  за пределы устройства.
* **DNS внутри proot**: Android не даёт `/etc/resolv.conf`, приложение генерирует свой файл и
  bind-mount'ит его в rootfs (`-b <file>:/etc/resolv.conf`); по умолчанию 1.1.1.1/8.8.8.8.
  В сети, где публичный DNS запрещён, потребуется свой резолвер (см. TODO).
* **Перезапуски**: экспоненциальный backoff 1→2→4→8→16 с, максимум 5 попыток; после лимита —
  `FAILED` с текстом и логом. Автоперезапуск можно выключить.
* **Фон**: foreground service `specialUse` + `START_STICKY` + partial wake lock. Android может
  убить процесс даже с FGS (OEM-агрессивные менеджеры) — сценарий восстановления: сервис
  перезапускается, сервер поднимается, клиент переподключается; пользователю предложено отключить
  оптимизацию батареи.
* **Автостарт при открытии приложения** выполняется из Activity (после первого кадра), а не из
  `Application.onCreate`: на Android 12+ запуск foreground service из фона запрещён, и падение в
  `onCreate` было бы фатальным.
* **Размеры**: bundle ~110–130 МБ (ubuntu-base ~28 МБ + opencode ~78 МБ, сжатые), распакованный
  ~350–450 МБ. Приложение требует ~1 ГБ свободного места с запасом (проверка перед установкой).
* **Shizuku** не требуется и не используется; интеграция — опция на будущее (TODO).

## 11a. Два варианта сборки: Full и Lite

* Один `applicationId` (`ai.opencode.android`, debug — `.debug`) для обоих flavor'ов: Full и Lite
  ставятся друг поверх друга как обновление, настройки/пароль/распакованное окружение сохраняются.
  Различаются только `versionNameSuffix` (`-full`, `-lite`) и содержимое ассетов.
* **Lite** — без bundle: ~19 МБ. Local mode требует URL/SHA-256 или импорт файла; Remote mode
  работает сразу.
* **Full** — `src/full/assets/local-env.tar.gz` (генерируется `:app:prepareFullBundle` или CI):
  ~125 МБ, Local mode ставится офлайн. Если бандла нет, сборка падает с понятной ошибкой — «пустой
  Full» выпустить нельзя.
* Bundle хранится в APK без сжатия (`androidResources { noCompress += "tar.gz" }`): он уже
  gzip, повторное сжатие только замедляет сборку и не уменьшает размер.
* **Full APK не предназначен для Google Play**: лимит APK в Play — 100 МБ (наши ~125 МБ), плюс
  сборка подписана debug-ключом. Распространение — GitHub Releases / прямая ссылка.
* Full-вариант не проверяется в обычном CI (сборка + 105 МБ бандла): он собирается в
  release-workflow, а `assembleLiteDebug`/`testLiteDebugUnitTest` — на каждый push.

## 12. Платформа и сборка

* `minSdk = 26` (Android 8.0): нужен `EncryptedSharedPreferences`, `Process` API и
  современный Compose; покрывает подавляющее большинство arm64-устройств.
* `targetSdk = 34`, `compileSdk = 34`, JDK 17, AGP 8.5.2, Gradle 8.9, Kotlin 2.0.21.
* «Приоритет arm64» реализован отсутствием собственного нативного кода: APK универсален и
  одинаково хорошо работает на arm64-v8a, armeabi-v7a и x86_64 (эмулятор). Для встроенного
  сервера требуется arm64 proot.
* Сборка проверяется в GitHub Actions на `ubuntu-latest` с предустановленным Android SDK.
  Локально в среде разработки этого задания не было ни JDK, ни Android SDK, ни доступа к
  `dl.google.com`/`repo1.maven.org`, поэтому верификация шла через CI, а не локальный запуск.

## 13. Ограничения текущей реализации

* Нет загрузки вложений/изображений в промпт, нет PTY-терминала, нет шеринга сессий.
* Local mode не проверялся на реальном arm64-устройстве в этой среде: тесты покрывают
  провижининг/health/логи/рестарты, но сам proot-процесс и rootfs требуют smoke-теста.
* Пагинация не реализована: 100 последних сессий, 200 последних сообщений.
* Нет push-уведомлений о `permission.asked` при свёрнутом приложении (SSE живёт, пока процесс жив).
* Инструментальные/UI-тесты и скриншоты отсутствуют; проверяется только JVM-логика.
* Приложение не проверялось на живом opencode-сервере в текущей среде (нет сети к серверу и
  устройства); контракты сверены с исходниками сервера и официальным SDK, но реальная
  интеграция требует ручного smoke-теста — чек-лист есть в README/TODO.

## 14. Юридические

* Репозиторий содержит только клиентский код (MIT). Код opencode не копировался; используются
  публичные HTTP-контракты. Название «opencode» принадлежит его авторам; это неофициальный клиент.

## 15. Исполнение `proot` на Android 10+

* С `targetSdk >= 29` SELinux не даёт приложению `execve()` файла из его приватной директории
  (`error=13, Permission denied`) — это и был реальный отказ Local mode на устройстве.
* Решение: `proot` (и его `loader`, и его bionic-библиотеки) поставляются как нативные библиотеки
  в `jniLibs`, а `jniLibs { useLegacyPackaging = true }` заставляет установщик распаковать их в
  `nativeLibraryDir` — единственный каталог, откуда приложение может запускать бинарь.
* Versioned-имена (`libtalloc.so.2`) в `jniLibs` недопустимы, поэтому `patchelf` переписывает
  `DT_SONAME` и `DT_NEEDED` на канонические `lib*.so`; это делает
  `.github/scripts/extract-proot-jnilibs.sh` в CI (и `:app:prepareProotJniLibs` локально).
* Приложение **никогда** не пишет в `nativeLibraryDir`: `EnvProvisioner` проверяет путь и падает,
  если цель установки оказалась внутри этого каталога.
* `PROOT_TMP_DIR` указывает в `noBackupFilesDir/opencode-env/tmp` (proot пишет туда свой loader),
  `PROOT_LOADER` — на `libproot_loader.so`, `PROOT_NO_SECCOMP=1` (seccomp-ускорение proot на
  Android-ядрах часто недоступно).
* Остаточный риск: если конкретная сборка proot не поддерживает `PROOT_LOADER` и всегда
  распаковывает свой loader в `PROOT_TMP_DIR`, exec этого loader-а из app data будет запрещён;
  тогда нужен статический proot без отдельного loader-а.
* Целостность зависимостей proot проверяется на трёх уровнях, чтобы «полурабочий» Full APK не мог
  уйти в релиз: скрипт упаковки требует непустой `proot-libs/`, обязательный `patchelf` и
  проверяет замыкание `DT_NEEDED` (все не-системные зависимости должны лежать рядом с
  `libproot.so`, а versioned-имена вроде `libtalloc.so.2` обязаны быть переписаны); Gradle-гард
  сверяет, что каждый файл из `src/full/jniLibs/arm64-v8a` реально попал в APK; `verify-apk.sh`
  читает `DT_NEEDED` уже из упакованного `libproot.so` и падает, если чего-то не хватает.
